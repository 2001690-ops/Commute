# V5.3.3 검토 사항 반영

이 변경은 첨부된 V5.3.3 소스를 기준으로 합니다. 기존 GitHub main의 Python 앱과는 별도 실행 구조이며 Python SQLite 자료를 D1으로 자동 이전하지 않습니다.

## 수정 내용

1. D1 한 행 2MB 제한: JSON 문서를 250,000 UTF-16 단위 이하 조각으로 분할합니다. 각 조각은 UTF-8 1MB 미만이며 surrogate pair를 분리하지 않습니다. 헤더, revision, 조각 저장과 이전 조각 정리는 D1 batch 하나로 처리합니다. 비교한 revision이 달라지면 현재 자료를 변경하지 않습니다. 기존 한 행 JSON도 읽으며 다음 정상 저장 때 새 형식으로 바뀝니다.
2. 수동 기록 수정: 입력창을 열 때 원본 스냅샷을 보관합니다. 서버는 원본 불일치와 원본 누락을 거부하여 오래된 입력창이 최신 수정을 덮어쓰지 못합니다.
3. 주휴의 월 경계: 근무일의 월과 해당 주 일요일의 월을 모두 검토 해제합니다. 관련 주휴 월이 마감됐다면 근무 수정·일정 변경·출퇴근 기록을 거부합니다.
4. 일정의 퇴근일: 다음 날 퇴근을 명시적으로 선택합니다. 일정·반복·복사·수동 입력 모두 출퇴근 24시간 미만, 유효 휴게시간을 검사합니다. 12시간 초과에는 별도 확인이 필요합니다. 기존 야간 일정은 그대로 읽힙니다.
5. 급여 달력: 결근·무급휴가·휴무는 0시간으로 표시합니다. 실제 완료된 0시간 기록도 예정시간으로 대체하지 않습니다. 관리자 달력, 직원 달력과 예상 기본급이 같은 선택 규칙을 사용합니다.
6. 예상 급여: 일정이 없더라도 완료된 실제 근무를 포함합니다. 일정이 전혀 없는 주에는 예상 주휴를 추가하지 않습니다.
7. 가불: 입력창에서 선택한 정산 월을 그대로 전송합니다.

## 배포와 DB 변경

GitHub 반영과 운영 배포는 별도입니다. 서버와 클라이언트 파일을 같은 버전으로 배포해야 합니다.

1. 운영 DB의 복구 지점/내보내기를 확보합니다.
2. 사용 중인 D1에 `drizzle/0001_document_chunks.sql`을 적용합니다. 신규 DB는 `0000_neat_nekra.sql`부터 순서대로 적용합니다. 프로젝트의 기존 마이그레이션 적용 경로를 사용하세요. 이 SQL은 기존 행을 삭제하지 않습니다.
3. 새 코드를 배포합니다. 첫 저장이 기존 JSON을 분할 문서로 변환하며 직원·근무·마감·계약·세션 데이터를 보존합니다.
4. 변경 후 조회·저장과 기존 직원 로그인을 확인합니다.

분할 문서 저장 후 이전 코드만 재배포하면 이전 코드는 새 헤더를 해석하지 못합니다. 롤백은 코드와 사전에 확보한 DB 복구 지점을 함께 사용해야 합니다. 운영 DB 마이그레이션이나 배포는 이 PR 작업에서 실행하지 않았습니다.

분할 저장은 행 크기 제한을 해결하지만 매 요청에서 전체 문서를 읽고 쓰는 구조는 유지합니다. 더 큰 규모에서는 테이블 정규화·월별 조회와 로그 보관 정책을 별도 적용하는 것이 좋습니다.

첨부된 Markdown은 텍스트 파일만 포함합니다. 참조된 `/yeondeok-logo-commute.jpg`는 이 패키지에 없으므로 배포할 때 기존 사이트의 이미지 자산을 별도로 복원해야 합니다. 운영 비밀값과 직원 자료는 포함하지 않습니다.

## 검증

- 일반 및 추가 회귀 테스트 14개 파일 통과. `tests/review-fixes.mjs`는 2MB 초과 자료, 한글·이모지 복원, 기존 자료 읽기, 중간 실패 원자성, 오래된 저장/수정, 월 경계 재검토, 마감 보호, 시간 입력, 달력·예상액·정산 월을 검증합니다.
- `node tests/stress-15-months.mjs`: 23개 시나리오, 직원 12명, 근무 4,704건, 요청 124회 통과.
- `node tests/d1-integration.mjs`: 로컬 workerd/D1에서 7,200,606 UTF-8 bytes를 12개 조각으로 저장·복원하고 오래된 revision 저장이 자료를 지우지 않음을 확인했습니다. 원격 DB에 연결하지 않습니다.
- `node node_modules/typescript/bin/tsc --noEmit`: 통과.
- `node scripts/run-framework.mjs build`: 통과.
- `git diff --check`: 통과.

실제 운영 D1, 인증 프록시, 카카오 전달과 실제 브라우저의 전 과정을 검증한 결과는 아닙니다.
