# 연덕갈비 출퇴근

Python 3.11 이상. `python -m pip install -r requirements.txt` 후 `python server.py init-admin`으로 최초 관리자를 생성하고 `python server.py`로 실행합니다. 기존 DB는 시작할 때 바로가기 테이블이 자동 추가됩니다. 먼저 백업하세요.

## 설정과 사용

- `YD_PUBLIC_ORIGIN=https://attendance.example.com`: 실제 HTTPS 서비스 주소, 경로 없이 설정. Host 헤더는 링크 생성에 사용하지 않습니다.
- `YD_DATA_DIR`: 데이터/백업 보관 폴더. 공개 웹 폴더 밖에 두세요.
- `YD_SECURE_COOKIE=1`(기본): HTTPS 역방향 프록시에서 운영. 로컬 HTTP 개발에서만 0.
- `YD_HOST`, `YD_PORT`: 기본 127.0.0.1:8080.

관리자 로그인 → 관리자 모드 → 직원별 바로가기 · QR에서 직원을 선택해 발급합니다. URL/QR을 해당 직원에게 전달하세요. 조회는 기존 링크를 유지하며 재발급은 이전 링크를 즉시 무효화합니다. 회수는 바로가기만 무효화하며 계정이나 기존 세션을 정지하지 않습니다.

직원은 URL/QR을 열고 자신의 아이디와 비밀번호로 로그인합니다. Android는 설치 버튼 또는 브라우저 메뉴, iPhone은 Safari 공유 → 홈 화면에 추가를 사용합니다. 직원별 manifest의 start_url이 해당 바로가기를 유지합니다. 회수/재발급 뒤에는 새 링크로 다시 설치하세요. HTTPS가 필요하며 브라우저별 설치 지원은 다를 수 있습니다.

## 보안

고유 경로는 무작위 공개 식별자이며 인증 토큰이 아닙니다. URL/QR/manifest에 비밀번호, 세션 토큰, CSRF 토큰, 이름 또는 직원 번호를 넣지 않습니다. QR은 서버 안에서 생성합니다. 바로가기 및 검증 API는 로그인 직원과 소유자가 다르면 거부합니다. 기존 근태 API는 세션 직원 ID로 읽기/쓰기를 수행하며 관리자 권한과 CSRF 검증을 유지합니다. 발급·재발급·회수는 관리자만 가능하며 직원 ID를 감사 로그에 기록합니다. 식별자는 인증 비밀은 아니지만 서버/프록시 접근 로그에 경로가 남을 수 있습니다.

서비스워커는 네트워크 전용이며 근태, 로그인, API 응답을 캐시하지 않습니다. 오프라인 근태 입력은 지원하지 않습니다.

## 검증

`python -m unittest -v`는 실제 HTTP 서버와 임시 DB로 미인증 차단, 관리자/CSRF 검증, 직원 격리, 링크 재발급·회수, 계정 비활성화, QR/manifest/아이콘 응답과 근태 회귀를 검사합니다. `node --check app.js`와 `node --check sw.js`로 문법을 확인합니다. 실제 스마트폰 설치와 운영 HTTPS 프록시는 배포 환경에서 별도 확인하세요.
